## 工程架构

主链由电压/IEPE相关输入选择、恒流激励、四阶模拟低通、AD8475差分驱动、双AD7768和Zynq组成。PL接收串行数据，组织24位转换码及32位缓存字，经FIFO和自定义AXI写通路进入DDR；PS完成命令处理、半区轮询读取和UDP上传，PC负责操作与保存入口。温度另设RTD调理、复用及MCU支路，单独维护其固件、通信和标定证据。

当前UDP应用载荷为1035B：11B头，之后8组“64B DDR复制字＋64B源码未写区”。每包复制区共512B、128个32位字；512B未写区不能作为额外样本。byte8及byte9—10为软件批/包计数，不是ADC帧号或独立秒表。通道物理映射、PC单位及时间定义应由同次真实资料关联。

按32.768MHz输入和PLL 50/125配置推导，MCLK为13.1072MHz，fast/64倍抽取对应51.2kSPS/通道。该值是条件推导；实际时钟的来源、验证状态及相应记录在技术附件中维护。

## 下一位接手者的顺序

1. 阅读本文件及[工程验证状态](technical-status.md)，核最终参赛稿与文件清单的SHA256；先辨清文档版本、R8候选和历史基线。
2. 取得准确核心板/DDR组织、K14与MIO13到连接器的映射、X1实际装配频率来源。已确认的6236A/PCB/自研选择不用再问。
3. 用户准备上板时，先记录板号、线缆、在线目标和实际文件，逐步保留加载/初始化日志；不要沿用历史target ID。
4. 一次试验一个ID，保留同次完整原始PCAP/PCAPNG、所有保存分段、PC可执行文件/配置hash及操作时间定义；用既有离线工具核复制字，再填明确槽→列/公式/窗口对账。
5. 数字身份、通道和时间定义明确后，分别获取实际ODR、标定、短接噪声、扫频、同步及冷启动材料。最终实物图片按用户安排最后加入。
